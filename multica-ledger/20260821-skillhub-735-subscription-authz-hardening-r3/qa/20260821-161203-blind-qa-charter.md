## 最危险反例

- 用户在 skill 可读时订阅，随后被移出 namespace / disabled / skill 变 PRIVATE 或 hidden；异步
  listener 若用旧 membership/账号或只在订阅时判断，会把 skill 标题、ID、版本与 SSE payload
  泄给已撤权 recipient。
- yank 更新 `latestVersionId` 后再处理事件；如果为“曾发布”建立旁路，会在新当前态下泄漏。
- eligibility loader 失败后若降级为原 subscriber 集合，fail-open 会形成批量泄漏。
- executor `CallerRunsPolicy` 饱和时任务可能在提交/after-commit线程同步执行；若测试把它误称为
  rejection，则既没有验证真实执行语义，也可能掩盖事务上下文与 sink 行为。
- old 8 callers 没改源码并不自动等于不漂移；共享 checker 内部委托/overload 分派仍需 differential
  和 existing suites 证明。
