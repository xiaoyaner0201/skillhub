# confirmPublish 发布事件修复计划（plan-r1）

## 冻结依据

### 事实

- live `iflytek/skillhub#731` 于 2026-08-19 UTC 仍为 OPEN；upstream `main` 与 fork `main` 均指向 `d2403bb5911953b8f53e62c3f0a9edc291363944`。
- 本工作分支 `20260819-skillhub-731-confirm-publish-event-r2` 从该 BASE 建立；本计划核验的源代码为 BASE 加账本初始化提交 `0efcc131e5e94dafb9519f701ecdf6d27be92c20`，生产代码未变化。
- `SkillReviewSubmitService.confirmPublish` 位于 `server/skillhub-domain/src/main/java/com/iflytek/skillhub/domain/skill/service/SkillReviewSubmitService.java:113-148`：校验后依次保存 `PUBLISHED` 版本、更新并保存 skill，但没有发布事件。
- 同类路径 `SkillPublishService.publishFromEntries` 位于 `server/skillhub-domain/src/main/java/com/iflytek/skillhub/domain/skill/service/SkillPublishService.java:571-573`：`autoPublish` 成功保存 skill 后发布 `new SkillPublishedEvent(skill.getId(), version.getId(), publisherId)`。
- 事件契约定义于 `server/skillhub-domain/src/main/java/com/iflytek/skillhub/domain/event/SkillPublishedEvent.java:3`，字段是 `skillId`、`versionId`、`publisherId`。本任务中的 `actorUserId` 映射到既有字段 `publisherId`，不改事件类型。
- 现有 `SkillReviewSubmitServiceTest` 已注入 mocked `ApplicationEventPublisher`，但 `submitForReview` 和 `confirmPublish` 测试均未断言事件；最小测试写集已存在于同一测试类。

### 假设与验证

- 假设：Spring 的事务事件语义和下游监听器无需改造；验证方式是本次只对 domain service 的同步 `ApplicationEventPublisher` 调用做单元测试，并跑 domain 模块相关及完整测试。若测试揭示事务监听差异，停止实现并回到规划，不扩大方案。
- 假设：`skillVersionRepository.save(version)` 与 `skillRepository.save(skill)` 任一抛错时方法中止，因此把发布调用放在两次保存之后即可保证本方法不在失败路径发事件；用 Mockito 分别让保存抛出运行时异常并断言 `never()` 验证。

### 判断

- “成功持久化为 `PUBLISHED`”在此服务的可测边界定义为：version save 和随后的 skill save 均正常返回。仅 version save 成功、skill save 失败仍是失败路径，不得发布。
- “恰好一次”定义为一次 `confirmPublish` 成功调用只调用一次 `eventPublisher.publishEvent`，且捕获事件的三个字段分别等于实际 `skill.getId()`、`version.getId()`、`actorUserId`。

## 方案比较与冻结决策

1. **推荐并冻结：在 `confirmPublish` 两次保存完成后直接发布事件。** 只改目标 service 与其单元测试，沿用 `SkillPublishService`、`ReviewService`、`PromotionService` 的既有发布方式；改动最小，失败边界可通过调用顺序和异常测试直接证明。
2. **备选：抽取统一的“持久化并发布”组件或引入事务提交后事件/outbox。** 可统一多条发布路径并强化提交语义，但会改变公共协作边界、扩大回归面，且 #731 没有要求解决跨进程可靠投递，因此不采用。

冻结方案为 1。禁止顺带重构事件体系、`SkillPublishService` 或监听器。

## 领域契约与不变量

- `confirmPublish` 是 PRIVATE skill 的 `UPLOADED`/legacy `DRAFT` 版本进入 `PUBLISHED` 的确认动作。
- `SkillPublishedEvent` 表示一个版本已经对既有发布链可见；生产者 payload 必须使用持久化实体 ID，不使用请求中未经实体核验的替代值。
- 不变量：任何前置校验失败均为 0 个 published event。
- 不变量：version save 或 skill save 抛错均为 0 个 published event。
- 不变量：成功保存 version 与 skill 后恰好 1 个 published event，payload 为 `(skillId, versionId, actorUserId)`。
- 不变量：`submitForReview` 只进入 `PENDING_REVIEW` 并创建 review task，始终为 0 个 `SkillPublishedEvent`。
