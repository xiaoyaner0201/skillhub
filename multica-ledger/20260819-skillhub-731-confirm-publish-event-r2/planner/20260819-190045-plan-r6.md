# Entry-purpose-specific subscriber authorization plan（plan-r6）

本计划 supersede `planner/20260819-182034-plan-r5.md`，但不改写 r5。相对 r5：**删除**全局统一 `CURRENT_READ` 与迁移所有production reads的方案；**新增**逐public entry的真实权限合同；**保留**archived PUBLIC skill detail可查询的明确兼容行为；**推荐**只为subscription/notification metadata exposure抽取purpose-aware小policy，不改skill detail、version/content、resolve/install或download入口；**保留**inactive account、fresh membership、platform role不扩权、yank pre-state purpose、批量fail-closed与最终notification sink。

原因是pinned source与`docs/oss-01-core-contract-freeze.md §7.8`已触发R5的falsification：skill detail与version/files/resolve/download并非同一read contract，公开archived skill detail必须继续成功。r1-r5、旧QA/Reviewer PASS与全部退回决定均保留为append-only历史，不授权R6实现或发布。

## 1. Source Contract / Repository Invariants / Plan Hypothesis

### Source Contract（明确上位要求）

- GitHub #731要求confirm-publish产生既有event；yank subscriber通知是正常control case。
- core contract freeze §7.8：`GET .../archived-skill`对PUBLIC archived skill成功并返回`status: ARCHIVED`；客户端据status判断不可新装。本任务不得夹带收紧该API。
- Plan Gate已确认：PRIVATE/跨namespace/inactive/stale authorization不能泄漏通知metadata；platform-only SUPER_ADMIN不得获得普通portal read不存在的穿透。

### Repository facts / invariants（按入口，不互相外推）

- 所有受保护authenticated portal entry先经过`AuthContextFilter`：missing/inactive account 401；async listeners不经过filter，必须自行batch重建active-account gate。
- skill detail：archived namespace非member拒绝；`VisibilityChecker`处理hidden/latest/visibility；**不检查skill.status**，因此PUBLIC archived skill detail可读。
- namespace discovery/list：只查询`SkillStatus.ACTIVE`，再按visibility过滤；archived skill不进入list，但direct detail仍可读。
- version detail/files/compare/list/resolve：调用`assertPublishedAccessible`，额外要求non-ACTIVE skill只能owner/current ADMIN/OWNER，随后hidden/visibility；具体version还受preview/published/installable规则。
- download/install：`assertCanDownload`做anonymous/visibility与archived namespace membership；内部`assertPublishedAccessible(skill)`明确要求skill.status ACTIVE；version必须PUBLISHED且installable（或受控draft preview）。archived skill不可下载/新装。
- subscription GET只返回caller自己的relationship boolean，DELETE清理自己的relationship；二者不返回skill metadata。PUT创建长期fan-out关系，需要以本任务定义的subscription purpose授权。
- publish/yank notifications暴露skill/version metadata，不提供文件内容或安装能力；但必须拒绝inactive、PRIVATE不合格、cross-namespace/stale recipients。

### Plan Hypothesis（可证伪）

- subscription PUT与subscriber notifications应复用一个**具体的 metadata-subscription purpose**，而非skill detail或install/content合同：允许与direct skill detail相同的archived-skill metadata compatibility，但保留account active、archived namespace current-member gate、hidden/publication/visibility/current membership；不添加skill.status ACTIVE门。
- `SUBSCRIPTION_METADATA_CURRENT`用于PUT与publish：current publication语义（latest=null owner-only）。
- `SUBSCRIPTION_METADATA_YANKED(preYankPublished=true)`用于yank：其余metadata gates相同，仅在no-fallback post-state不误套latest=null，从而保持合法yank control。
- 此purpose不修改也不被skill detail/version/download调用；可以复用/委托现有`VisibilityChecker`内核及单独namespace archived gate，但必须封装为一个小policy供PUT+两个listeners共同调用，不能让listener各自拼规则。

### Non-goals

- 不迁移或统一skill detail/discovery/version/files/compare/resolve/download/install合同；不改变archived PUBLIC detail成功或archived不可安装差异。
- 不扩platform角色，不自动删stale relation，不改GET/DELETE、payload、lifecycle、audit、search、preference/outbox。
- 允许R4最小yank publication context；event禁止recipient/account/membership/role snapshot。
- 本阶段不改生产/测试代码、不建Coding Stage、不创建PR/merge/release。

## 4. 方案比较与冻结选择

### A（推荐）：小型purpose-aware `SubscriptionMetadataAccessPolicy`

policy只服务PUT与publish/yank subscriber metadata exposure；组合account active、archived namespace member gate与existing visibility规则，purpose仅区分current publication和verified yanked publication。不改其它read entries。

优点：seam与#731 fan-out风险一致；共享一处避免PUT/listener漂移；保留archived detail兼容和content/install更严格合同；可批量供facts避免N+1。代价：这是新purpose，不声称等同某个现成完整入口，必须由差分tests证明边界。

### B：复用skill detail完整方法/统一所有read policy

会耦合DTO/projection并产生N+1；更关键是R5式统一会误收紧archived detail或放松content/install。拒绝。

### C：复用version/download严格合同

可减少metadata泄漏，但会让archived PUBLIC subscription/yank control随skill.status被拒绝，并把“收到metadata通知”等同“可安装”，改变产品合同。拒绝。

冻结A。现有`VisibilityChecker`只作为visibility子规则；policy明确加入account与namespace lifecycle，明确不加入skill.status gate。

## 7. 可执行 RED/GREEN与最终sink

- 差分control：同一PUBLIC archived skill，direct detail=success+ARCHIVED；discovery absent；version/files/resolve/download按各自现有严格gate拒绝或仅manager继续；metadata PUT/publish/yank按R6 purpose处理。
- inactive candidate：publish/yank两post-state 0 persist/SSE。
- archived namespace：current member继续visibility；removed/nonmember 0且PUT forbidden。
- PRIVATE/hidden/cross-ns/platform-only SUPER_ADMIN：不合格者publish/yank 0且PUT forbidden。
- yank no-fallback：合法PUBLIC/NAMESPACE_ONLY/PRIVATE-admin subscriber仍1；失权者0。
- mixed：recipient精确等于active+metadata-purpose eligible+nonpublisher/actor。
- account/namespace/membership异常：整批0，无partial。
- GET/DELETE：active caller仍看到/清理own stale relation。
