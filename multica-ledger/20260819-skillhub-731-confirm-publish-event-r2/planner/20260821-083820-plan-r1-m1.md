## 1. Source Contract、事实、推导与假设

### 原始事实（FACT）

- `SkillSubscriptionService.subscribe` 对拒绝路径抛出 `error.skill.subscription.noPermission`，但 EN/zh bundle 均缺 key；`ApiResponseFactory.error` 的 default message 是 code，故当前 403 会显示裸 key而非 500。
- `onSkillPublishedForSubscribers` 与 `onSkillVersionYankedForSubscribers` 在候选订阅者非空后读取 namespace，`Optional.empty()` 以 `null` 传给 eligibility；`SubscriptionMetadataAccessPolicy` 对 null namespace 返回 false，当前最终 recipient 集为空。
- 两个 listener 共用 `SkillPublishedEvent`：owner notification、subscriber notification 和 search-index rebuild 均会被 confirm-publish 新事件触发；search consumer 虽未在 F1/F2 写集，仍是新可达行为。
- `PostgresFullTextQueryService` 在 query sink 只允许 PUBLIC，或登录用户所在 namespace 的 NAMESPACE_ONLY；PRIVATE 不进入 portal search。其 SQL 同时过滤 active skill、hidden=false 与 namespace lifecycle。
- 存量 `skill_subscription` 行不在本轮删除；`listMySubscriptions` 会将 retained row 投影成 `SkillSummaryResponse`，`isSubscribed` 会返回自己的关系布尔值，二者当前没有 subscription metadata policy gate。

### 明确要求（REQUIREMENT）

- 两个 bundle 各新增且仅新增 `error.skill.subscription.noPermission`；不重排条目，不改异常体系。
- 两个 null-namespace 分支各记录一条 WARN，字段仅含 `skillId`、`namespaceId`，无 subscriber ID、列表或其他用户可识别信息；null 仍全拒绝。
- namespace 非 null 时，发布/yank 的收件人集合必须与改动前逐元素一致，而不只是数量一致。
- PR 草稿必须落在 `multica-ledger/**`；不得实现 migration、prune、DB 或 workflow 变更。
- 工程链交付 READY exact tree；公开分支同步、PR 正文修改、Draft→Ready 与 CI checks 读回属于 Publication 责任面。

### 合理推导（INFERENCE）

## 4. 方案比较与冻结选择

### A（冻结）：两处显式 WARN + 文件级 ResourceBundle probe + 同 fixture 基线差分

在两个 listener 方法各自的 namespace lookup 后以 `if (namespace == null)` 打同一 WARN，随后继续调用既有 eligibility，让原 fail-closed 路径保持原样。F1 在既有 app test suite 内加载真实 bundles；F2 同时做日志 sink、null final sink 和 frozen/candidate recipient-list 差分。

优点：生产 diff 最小；不引入 helper/control-flow 变化；测试能分别杀死“缺日志”“PII 泄漏”“收件人漂移”“bundle 仍 fallback”四类缺陷。代价：两处日志语句重复，但重复恰好对应两个独立事件入口且避免为两行日志抽象新 helper。

### B：提取 `loadNamespaceOrWarn` helper

可去掉重复，却会把 lookup/日志/control-flow 合并进新 seam；对两处极小定向修复收益不足，且更容易改变异常传播或早退语义。拒绝。

### C：namespace null 时 WARN 后立即 return

最终收件人同为零，但跳过现有 eligibility 的 account/membership batch行为，改变调用序列、异常/观测语义，无法满足“行为仅增加日志”。拒绝。

## 8. Council nomination（HIGH_RISK）

1. `trust-boundary` — **Bruce Schneier-style**：专查 `published-subscriber-observability` / `yanked-subscriber-observability` 的 `DIAGNOSTIC_WITHOUT_PII`、`CURRENT_READ_AUTHZ_UNCHANGED`。必须回答：null namespace WARN 是否泄露 candidate identity；removed/downgraded/cross-namespace 是否仍为 0 sink；shared event 是否让 PRIVATE metadata 经 owner/search/notification 旁路可见；日志或 readback 是否形成新的数据外泄面。非 dissent。
2. `event-state-consistency` — **Martin Kleppmann-style**：专查 `published-search-control`、两个 fan-out path 的 AFTER_COMMIT/Async 与 `SEARCH_QUERY_ISOLATION_UNCHANGED`。必须回答：confirm-publish 后 search rebuild 与 subscriber fan-out 是否消费同一 committed state；namespace 缺失与 repository exception 是否被错误等价；search document 可包含 PRIVATE metadata时 query boundary是否仍阻止用户可见结果；异步失败是否只影响相应 consumer而不伪造另一个 consumer 成功。非 dissent。
3. `evidence-dissent` — **Kent Beck-style**：专查 `subscription-denial-localization` 与两个 non-null elementwise probes 的 `RECIPIENT_SET_UNCHANGED_BY_LOGGING`。必须回答：真实 bundle probe 是否会在旧 tree 因裸 key 失败；日志 probe 是否观察 `NotificationEventListener` 真 logger而非 mock；recipient 比较是否逐 tuple且跨 frozen/candidate clean tree；最终 notification row/SSE 是否在 mock 最外边界断言；**本方案在什么条件下是错的，哪些仍全绿的 probe 会暴露不了该错误**。承担 dissent。

Declined lenses：Leslie Lamport-style 不单列，因为本轮不改 transaction/event ordering，时序问题由 event-state-consistency lens 覆盖；Linus Torvalds-style 不单列，因为生产 diff 只有 bundle 行与两条 WARN，无新 API/抽象，独立代码品味 lens 无实质增量。

## 9. Falsification / PLAN_GAP

- 两条 listener 实际还有第三个 namespace-null subscriber入口，或动态 consumer 新增 user-visible sink；
- WARN 必须含 subscriber/user信息才能诊断，或 logger/config 无法在不改依赖的情况下验证；

- search query 存在绕过 `PostgresFullTextQueryService` 的用户可见入口且会返回 PRIVATE document；
