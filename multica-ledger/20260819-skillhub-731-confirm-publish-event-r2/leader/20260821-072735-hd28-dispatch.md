## 2. 风险分级：`HIGH_RISK`（机械判定，不可自行降级）

命中 `multica-engineering-delivery` 风险触发器清单中的四类：

1. **authorization**：`SubscriptionMetadataAccessPolicy` 的读权限过滤；
   `PUT /skills/{id}/subscription` 由「任意已存在 skill 均成功」变为对无读权限方 403。
2. **PRIVATE / 跨 namespace**：canonical 读模型 `PRIVATE -> owner only`，涉 namespace 成员角色。
3. **event / notification / fan-out / subscriber**：`SkillPublishedEvent` →
   `NotificationEventListener#onSkillPublishedForSubscribers` 的收件人扇出。
4. **async listener**：上述 listener 为异步消费者。

F2 的**改动行**看似只是加一条 `log.warn`，但其所在位置正是扇出链上的 fail-closed 授权分支。
按 "changed lines ≠ changed behavior"，分级依据行为面而非 diff 体积，故不降级。

分级后果（本 Issue 强制生效）：

- Plan 之前必须先跑独立 `BEHAVIOR_DISCOVERY` Run，生产方非 Planner；
- QA 拆 blind Charter 与 execution 两 Run；
- Review 拆 `BLIND_BEHAVIOR_AUDIT`（Pass 1）与 `EVIDENCE_CHALLENGE`（Pass 2）两 Run；
- Planner 在 Plan 中提名 2–3 个具名 lens 组成 Review Council，含至少一名 `dissent_role`；
- Stage 只接受绑定 artifact digest / inventory digest / exact tree / validator hash / 真实 Run ID 的 PASS receipt。
